# Сравнение Git и SVN

Ответы на вопросы задания 4 практической работы № 2.

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это указатель на коммит (несколько десятков байт). Файлы не копируются: объекты лежат в общем графе, а переключение ветки меняет только `HEAD` и рабочее дерево. Поэтому создать ветку можно мгновенно, даже в большом репозитории.

В SVN ветка исторически оформляется как копия каталога на сервере (`trunk` → `branches/feature`). Серверу нужно создать новую путь-копию, а клиенту — часто выкачать её. Merge в SVN хуже отслеживает общую историю, поэтому ветвление считают «дорогим» и используют реже.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Полноценный коммит без сети сделать нельзя. SVN централизованный: ревизия появляется только на сервере. Без интернета можно менять файлы локально, но нельзя сохранить ревизию, переключать ветки с историей и смотреть чужие коммиты.

В Git коммит — локальная операция: на компьютере есть полная копия репозитория. Сеть нужна только для `push` и `fetch`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты в госсекторе и банках, где уже настроены права, хуки и регламенты вокруг SVN.
- Очень большие деревья с тяжёлыми бинарными файлами, когда удобнее выкачивать одну папку, а не клонировать весь репозиторий.
- Команды, которым нужна жёсткая централизация: один сервер как единственный источник правды и простая модель «пишем в trunk».

Для нового учебного и продуктового проекта разумный выбор — Git.
